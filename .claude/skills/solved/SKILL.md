# 解答のコミット

対象のコンテスト：$ARGUMENTS

## 1. フォルダを決める

- 名前からコンテストのフォルダを探す（例：`abc483` は `atcoder/abc/451-500/abc483`）。
- 名前がなければ、`git status --short` で未追跡か変更のあるコンテストのフォルダを探す。1つならそれを使い、複数あれば尋ねる。

## 2. ファイルを決める

- 対象は、そのフォルダの `src/<言語>/` にある未追跡または変更済みの解答に限る。ほかのフォルダの変更は含めない。
- [templates](../../../templates/java/README.md) のテンプレートから変えていないファイルと、空のファイルは除く。
- 解答に秘密情報（セッション、パスワード、トークン）がないか読んで確かめる。
- `*.iml` は Git の管理外なので、追加しない。

## 3. IDEA のモジュール登録を確かめる

`.ide/idea/.idea/modules.xml` に `<コンテスト名>.iml` の行があるか確かめる。なければ、AtCoder のコンテストなら `python scripts/new-atcoder-module.py <コンテスト名>` で登録できることを添えて報告する（自分では実行しない）。このファイルは Git の管理外なので、コミットには含まれない。

## 4. コミットする

- メッセージは `Solved: ABC483 [A ~ G] (Java, C++)` の形式で書く。コンテスト名は大文字にする。
- 範囲には、今回コミットする最初と最後の問題を指定する。1問だけなら `[E]` と書く。
- 今回コミットする解答の言語を末尾の半角括弧に 1 回ずつ書き、複数なら `, ` で区切る。1 問を Python だけで解いた場合は `Solved: ABC483 [E] (Python)` と書く。
- 問題が連続していないとき（A、B、D など）は、範囲の書き方を尋ねる。
- `git add` は対象のファイルを名指しする。
- push はしない。

## 5. 報告する

コミットしたファイル、除いたファイルとその理由、モジュール登録の有無を伝える。
