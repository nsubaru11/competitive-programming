## 問題に応じた実行環境の選び方

次の表は、各環境の特徴から考えた「最初に試す環境」の目安であり、このリポジトリでの速度比較結果ではありません。
提出先で利用できる言語・バージョン・ライブラリを確認し、制限が厳しい場合は最大ケースに近い入力で実行時間とメモリを比較します。

| 問題・処理の特徴                                                             | 最初に試す環境       | 選ぶ理由・判断のポイント                                                                                                                                        |
|------------------------------------------------------------------------------|----------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------|
| 四則演算、条件分岐、小さな全探索など、短時間で終わる処理                     | CPython              | JITの準備による利点が出にくいです。短い処理ではまずCPythonで十分か確認します。                                                                                  |
| 長いループ、DP、配列更新など、Pythonで同じ処理を繰り返す                     | PyPy                 | 繰り返し実行されるPythonコードをJITが最適化できます。                                                                                                           |
| BFS・グラフ探索・データ構造の操作が多い                                      | PyPy                 | Python側の反復処理が主なら候補になります。組み込み関数・ライブラリの処理が主ならCPythonとも比較します。                                                         |
| 型がそろった数値ループ、重いシミュレーション、数値中心のDP・Moのアルゴリズム | Codon                | 対応する構文・APIで書け、途中の計算も64bitに収まる場合、ネイティブコンパイルを活用できます。                                                                    |
| `split/join/replace` など、文字列の組み込み処理が中心                        | CPython              | まず組み込み処理の性能を利用します。文字を1つずつ処理する長い自作ループならPyPy/Codonも比較します。                                                             |
| 巨大な整数、64bitを超えるビット集合、桁数の大きな数論処理                    | CPython              | 任意精度整数をそのまま使えます。長いPythonループも多い場合は、同じく任意精度整数を持つPyPyとも比較します。Codonの通常の `int` は64bit。                         |
| NumPy・SciPyなど、既存のCPython向けパッケージを利用する                      | CPython              | この構成でパッケージをそろえている環境を利用します。PyPy/Codonへ切り替えても、同じパッケージがそのまま使えるとは限りません。                                    |
| Python 3.12以降の構文・APIを利用する                                         | CPython 3.13         | このPyPyはPython 3.11相当なので、3.12以降の機能は前提にできません。CodonもCPython 3.13との完全互換ではありません。                                              |
| 深い再帰のDFS・木DP                                                          | CPython / PyPyで確認 | 再帰上限に加えて、実際の深さ・メモリ使用量を確認します。必要なら明示的なスタックによる反復へ変えます。Codonなら深い再帰が自動的に安全になるわけではありません。 |
| 対話問題                                                                     | CPythonを起点に選ぶ  | 出力を送るタイミングが重要。`print(..., flush=True)` を使い、全入力の事前読み込みを避けます。環境の変更だけではflushの問題は解決しません。                      |
| 入出力やライブラリ呼び出しが時間の大半を占める                               | CPythonを起点に比較  | JITやネイティブ化だけでは改善しにくいです。まず入力の読み方・出力回数を見直します。                                                                             |
| メモリ制限が厳しい                                                           | 実測して選ぶ         | JITを含む実行環境とデータ表現の両方が影響します。配列・辞書の持ち方や入力の一括保持も含めて比較します。                                                         |

PyPyは主にPythonで書かれた処理を高速化します。JITの準備時間があり、短い処理や、既にCなどで実装された関数の呼び出しが中心の処理では利点が出にくいです。
[PyPy FAQ](https://doc.pypy.org/faq.html#how-fast-is-pypy)、[性能調整の考え方](https://pypy.org/performance.html)を参照してください。
Codonも、既存のネイティブライブラリ呼び出しや入出力が支配的な処理では、大きな改善が得られるとは限りません。
[Codon FAQ](https://docs.exaloop.io/start/faq/)を参照してください。

## CPython 3.13.7の特殊な設定

| テンプレートのコード                       | 意味・使う場面                                                                                                                                                         |
|--------------------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `input = sys.stdin.readline`               | 組み込み `input()` を行入力へ差し替えます。行末の改行を除去しないため、数値は `int(input())`、文字列は `input().rstrip("\r\n")` と読みます。                           |
| `sys.setrecursionlimit(1_000_000)`         | Pythonが許可する再帰の深さを引き上げます。再帰DFSなどで既定の上限を超える場合に使います。高速化やスタック容量の拡張ではなく、100万段の再帰が動く保証でもありません。   |
| `sys.set_int_max_str_digits(0)`            | 整数と十進文字列の相互変換にある桁数制限を解除します。例えば5000桁の入力を `int(...)` にする場合に関係します。整数演算自体の精度や再帰上限を変える設定ではありません。 |
| `T = TypeVar("T", int, float, str)`、`Any` | IDEの型検査・補完のための型ヒントに使います。値を機械語の整数へ固定したり、実行を高速化したりする設定ではありません。                                                  |

行入力の差し替えは、空行では `"\n"`、EOFでは空文字列を返します。改行だけを取り除く場合は `rstrip("\r\n")` とし、末尾の空白まで取り除きます。
`rstrip()` と使い分けます。
再帰上限・整数の文字列変換上限の仕様は [Pythonのsysリファレンス](https://docs.python.org/3.13/library/sys.html)を参照してください。

## PyPy 3.11-v7.3.20の特殊な設定

行入力、再帰上限、整数の文字列変換上限、型ヒントはCPythonのテンプレートと同じ目的で設定しています。
追加しているのは次のJIT設定です。

```python
try:
  import pypyjit

  pypyjit.set_param("max_unroll_recursion=-1")
except ImportError:
  pass
```

| コード                     | 意味・使う場面                                                                                                                                |
|----------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------|
| `import pypyjit`           | PyPyのJITを調整する専用モジュールを読み込みます。                                                                                             |
| `max_unroll_recursion=-1`  | 再帰関数をJITで展開する設定を調整し、再帰の展開を抑えます。再帰を多用する処理で比較する設定であり、すべての問題が速くなるわけではありません。 |
| `except ImportError: pass` | CPythonで確認・デバッグするときに、PyPy専用モジュールがなくても起動できるようにします。CPythonでこのJIT設定が有効になるわけではありません。   |

`max_unroll_recursion` は再帰の許可深さを変える設定ではありません。深さの上限は `sys.setrecursionlimit` と別です。
速度が問題になる場合は、この設定の有無を同じ入力で比較します。
型ヒントを加えること自体はJITの高速化スイッチではありません。
[JITパラメーター](https://doc.pypy.org/jit_help.html)、[型ヒントと性能](https://doc.pypy.org/faq.html#would-type-annotations-help-pypy-s-performance)
を参照してください。

## Codon 0.19.3の特殊なコード・実行方法

```bash
codon run --release solution.py
```

| コード・仕組み                     | 意味・使う場面                                                                                                                               |
|------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------|
| `--release`                        | 最適化付きでネイティブコードへコンパイルして実行します。`sys` の設定で高速化するのではなく、コンパイル時の最適化を利用します。               |
| 引数の型を省略した関数             | Codonが呼び出し元から型を推論し、その型に合わせたコードを生成します。このテンプレートでは未対応の `typing.TypeVar` を読み込みません。        |
| 組み込み `input()`                 | Codonのネイティブ実装で行入力を行い、改行を除去します。CPython・PyPyのテンプレートのような `sys.stdin.readline` への差し替えはしていません。 |
| 通常の `int`                       | 符号付き64bit整数であり、CPython/PyPyの任意精度整数とは異なります。値だけでなく、掛け算などの途中値も範囲に収まるか確認します。              |
| CPython向けの `sys` 設定を入れない | 0.19.3では `sys.setrecursionlimit`・`sys.set_int_max_str_digits` などを同じようには使えません。CPythonの実行設定をコピーしません。           |

[Codonの型推論](https://docs.exaloop.io/language/generics/)、[整数型](https://docs.exaloop.io/language/lowlevel/)を参照してください。
Pythonとの互換性は完全ではなく、0.19.3で使える構文・標準APIを確認します。このテンプレートの設定と起動は、インストール済み0.19.3でも確認しています。

`codon run` はローカルではコンパイルも行います。実行時間を比較する場合は `codon build --release -o main solution.py`
で作った実行ファイルを計測し、コンパイル時間と実行時間を区別します。
CPython/PyPyは実際の提出と同様に、新しいプロセスの起動から計測し、PyPyのJIT準備時間も含めます。
